# 交互动画创意方法

当用户询问“可以做什么效果”、只有目标没有动作方案，或现有动画缺少表达目的时读取本文件。

## 从作用开始

先确定动画承担的主要作用，只选一个主作用：

- 引导注意：让用户发现可以交互的对象。
- 解释关系：展示输入、过程、因果、层级或空间关系。
- 表达进度：让连续位置、阶段或完成度可感知。
- 提供反馈：确认悬停、拖拽、提交、成功、失败或等待。
- 奖励探索：让用户主动操作后获得有意义的变化。
- 营造情绪：建立轻快、克制、紧张、柔和或机械的节奏。

没有作用的动作只是装饰。装饰可以存在，但必须低成本、可暂停且不干扰内容。

## 先审计对象的运动潜力

不要从“场景视频、绿幕、雪碧图、视差、跟随鼠标”开始。先检查对象本身：

| 维度 | 要问的问题 | 常见变化 |
|---|---|---|
| 结构 | 由哪些层、壳体、部件和连接组成？ | 组装、拆解、爆炸图、剖切、折叠、展开 |
| 功能 | 输入、处理和输出是什么？ | 启动、传递、计算、充能、响应、完成 |
| 材质 | 表面和内部能否改变可见性？ | 透明、X 光、线框、液态、熔化、结晶 |
| 空间 | 用户应该从哪里看到哪里？ | 环绕、推进、拉远、穿越、进入内部、越过尺度 |
| 状态 | 前后状态有什么意义？ | 开关、空满、快慢、新旧、普通与专业模式 |
| 信息 | 哪些关系需要被理解？ | 分流、汇聚、映射、因果、比较、层级、反馈 |

一个手机可以从完整外观变成爆炸图、进入芯片内部、沿信号路径点亮，再重新组装。
一个软件产品可以从界面进入数据管线，展示处理过程后回到结果。例子只说明方法，不是
Skill 的默认题材。

## 动作语法

从下面选择能表达内容的动词，不要把所有变化塞进一条动画：

- 结构：assemble、disassemble、explode、separate、stack、fold、unfold、peel、cutaway。
- 形态：morph、inflate、compress、grow、dissolve、crystallize、flow。
- 材质：reveal、x-ray、wireframe、scan、heatmap、translucent。
- 空间：orbit、dolly、macro、fly-through、tunnel、parallax、scale-jump。
- 信息：trace、route、pulse、branch、converge、compare、highlight。
- 状态：activate、charge、complete、unlock、switch、transform。

## 把输入映射到变化

| 输入 | 连续参数 | 适合的视觉回应 | 参数结构 |
|---|---|---|---|
| scroll | 全页或局部进度、速度 | 拆解、组装、穿越、材质和章节转场 | linear |
| pointer | 方向、距离、速度 | 环绕视角、聚焦部件、剖切深度、光照扫描 | circular / 2d |
| drag | 位移、角度、拉伸量 | 直接拆分、撕开、旋转、比较前后 | linear / 2d |
| touch / orientation | 倾斜、方向、力度 | 重力、内部层差、液体、空间视差 | 2d |
| audio | 音量、频谱、节拍 | 频谱结构、脉冲、形变、排列 | linear / data |
| data / state | 数值、阶段、成功失败 | 流量、热力、完成度、模式切换 | linear / discrete |

### 旋转与视向交互物理分类

交互驱动的“转动”必须在 Concept Contract 中严格分型，禁止笼统写“转动 360°”导致模型误解旋转轴：

1. **时钟圆周注视（Clockwise Gaze Orbit，`parameter_space: circular`）**：
   - **视觉物理**：**面部/头部始终朝向镜头**。虚拟目标在屏幕正前方垂直视平面的圆周上移动，主体的视线和面部朝向呈圆锥形旋转跟随（12点钟仰视 → 3点钟右偏 → 6点钟俯视 → 9点钟左偏 → 12点钟归位）。
   - **绝对禁忌**：**严禁绕垂直 Y 轴横向自转把后脑勺露给用户**。
   - **适用场景**：官网吉祥物、3D 伴侣、数字人头像跟随光标或滚动环顾。
2. **水平有限摆头（Horizontal Yaw Scrub，`parameter_space: linear`）**：
   - **视觉物理**：左右摆头转角（如 $-60^\circ \sim +60^\circ$），不闭环，有清晰极限端点与中间正视状态。
   - **适用场景**：横向滚动条、视差滑动、光标 X 轴水平巡视。
3. **展台水平全周自转（Turntable 360°，`parameter_space: circular`）**：
   - **视觉物理**：主体绕自身垂直中心 Y 轴水平自转 360 度，依次呈现正面、侧面、背面与完整三维全貌。
   - **适用场景**：电商硬件产品（手机、腕表、汽车、球鞋）全景展示。

同一个对象至少考虑三类方向：结构变化、空间或镜头变化、材质或状态变化。用户已经明确
动作时，不为凑数量增加无关方向。指针与手势随动输入细腻，若源帧数不足产生换帧阶梯感，应在帧准备中评估插帧。

## 影视级一镜到底创意洞察库

利用首尾帧链条（$K_0 \to K_1 \to K_2 \dots$）与分段 AI 视频，能够通过滚动驱动实现震撼的影视级连续一镜到底（Continuous One-Shot）。每个范式均有明确的物理锚点与关键帧接力法则：

### 1. 无限尺度穿透（Powers of Ten / Micro-to-Macro Zoom-Through）
- **镜头语言**：摄影机从宇宙或宏观全景急速推近，跨越数万倍空间尺度穿透微观核心。例如：外太空地球全景 → 穿越平流层云海 → 城市霓虹天际线 → 穿过大厦玻璃窗 → 桌面微缩芯片 → 穿透硅片晶体管进入量子光子数据世界。
- **首尾帧要点**：确立严格的“中心视觉锚点（Center Visual Anchor）”。前一段视频终点画面正中心的微观物体，必须是下一段视频起点的全局主体；每段视频只负责一级尺度缩放（如 100x），分段串联。

### 2. 实体视线遮挡转场（Object Wipe & Occlusion Pass-Through）
- **镜头语言**：参考《1917》《鸟人》。摄影机跟随主体在不同空间穿梭，利用前景高速掠过的实体障碍物（如粗大立柱、门洞边框、呼啸而过的列车、巨大岩壁）完全遮挡画面的瞬间（全屏暗部或纯实体占比达 100%），天衣无缝地切入全新世界。
- **首尾帧要点**：以“遮挡完全占据画幅”的那一瞬间作为前一段的尾帧 $K_{n,\text{tail}}$ 和后一段的首帧 $K_{n+1,\text{first}}$。因为画面在此时完全被前景实体覆盖，背景在遮挡背后悄然置换，实现零跳变空间跃迁。

### 3. 时光风霜流转剥蚀（Temporal Weathering & Era Timewarp）
- **镜头语言**：摄影机机位与主体轮廓严格锁定，随着用户向下滚动，数百年沧桑在数秒内席卷画面——从现代崭新的工业机械 → 饱经战火的风蚀锈蚀废墟 → 赛博霓虹数字重生；或从冬季枯木积雪 → 春风拂过花朵极速绽放 → 烈日盛夏。
- **首尾帧要点**：通过同一套精准的三维姿态与机位生成不同时代状态的图片作为关键帧。AI 视频模型只需负责中间的材质溶解、氧化生锈或光影四季演变，几何形状完全稳定。

### 4. 瞳孔/透镜拓扑嵌套（Reflective Portal Zoom-Through）
- **镜头语言**：摄影机从环境全景快速向前推轨，直奔角色的眼眸（或宇航员头盔面罩反光、光滑水滴、黑曜石镜面）。瞳孔倒影中的神秘场景随推近越来越大并充满画幅，镜头“咚”地穿透瞳孔，倒影瞬间化为真实宏大的全新场景。
- **首尾帧要点**：前一段视频终点为眼眸极致微距特写（倒影细节清晰可辨），后一段视频以该倒影场景的全景作为首帧开场，通过空间嵌套完成世界跳转。

### 5. 重力空间折叠倒错（Inception Dimension Fold / Gravity Inversion）
- **镜头语言**：参考《盗梦空间》《奇异博士》。摄影机沿着笔直大道前行，随着滚动，地平线向上弯曲 90 度折叠为天空，两侧大楼在头顶闭合；或者重力翻转 180 度天地倒错，物理法则随滚动动态颠覆。
- **首尾帧要点**：利用对称几何构图。首帧为标准地平线街景，尾帧为垂直折叠或倒置构图，视频模型负责中间流体般的建筑立面空间弯曲形变。

### 6. 建筑透视穿墙剖切（Architectural Cutaway Dolly）
- **镜头语言**：摄影机保持恒定高速推轨，直接撞向摩天大楼的混凝土实体外墙。外墙在接触瞬间如同 X 光剖面或线框切片般剥离溶解，镜头平滑穿入大楼内部，俯瞰复杂的服务器机房与光纤数据流，再从另一侧窗户穿透飞向高空。
- **首尾帧要点**：外墙完整态为首帧，外墙剖切后的内部结构为尾帧，保持镜头匀速推进，避免突然减速或硬切。

## 把创意变成关键帧

Oil Motion 的视觉生产固定为“先生图，再生视频”。每个方向都要先回答：

1. 起始图是什么。
2. 结束图是什么。
3. 是否需要中间关键帧才能让变化稳定。
4. 哪两张相邻关键帧组成一段视频。

- 真实产品的 Logo、孔位、部件数量和比例不能漂移时，先用原始产品图片生成并验收每张关键帧，不让视频模型只凭文字猜终点。
- 单段视频只完成一个主要语义变化，例如“整机拆开”或“镜头进入芯片”，不要把多个大变化塞进同一段。
- 多阶段叙事使用 `K0 → K1 → K2…`：先生成全部关键帧，再分别生成 `K0→K1`、`K1→K2` 视频。
- 文字、数字、进度和高亮由程序在运行时覆盖；主要画面与转场仍来自关键帧约束的 AI 视频。

例如“手机完整态 → 爆炸图 → 芯片特写 → 重新组装”需要四张关键帧和三段视频，
不是一条长提示词。这样每段更稳定，也便于滚动正反播放和单独重做。

## 让三个方向真正不同

三个方向至少在两项上不同：

- 不同驱动方式。
- 不同参数空间。
- 不同表达作用。
- 不同运动主体或结构。
- 不同关键状态或镜头路径。

避免给出三个只是速度、幅度或颜色不同的同类方案。

## 判断语义与几何

- 部件连接、壳体开启、材质形变、关节、抓握、毛发、布料和遮挡属于语义运动。
- 位移、缩放、旋转、裁切、路径、惯性和参数映射属于几何运动。
- 只要移动整张图片会破坏接触或遮挡关系，就生成完整语义动作。
- 位移、时间、文字和参数映射交给程序；主体本身的主要视觉变化仍由 AI 视频生成。

## 按显示尺度选择复杂度

- 小型控件：动作短、轮廓清晰、状态明确，只生成必要的短片段和少量帧。
- 内容插画：允许一个主要语义动作，控制持续时间和资源体积。
- Hero 或全屏叙事：先锁 Concept Contract 的背景归属，再做资源预算；路线选择按
  [delivery-selection.md](delivery-selection.md) 的决策顺序执行。
- 长页面连续滚动：区分全页进度和局部章节进度，不默认把整页映射到一条视频。

## 生成创意方向

方向必须来自对象证据，而不是来自上一次项目。每个方向写清：

1. 起始和最终状态。
2. 哪些结构或材质真正改变。
3. 镜头是否移动，移动轨迹是什么。
4. 输入如何映射到进度，反向操作是否成立。
5. 哪些画面由关键帧图片锁定，哪些中间变化由 AI 视频生成，哪些文字与交互由程序控制。
6. 在目标尺寸下的清晰度、帧数和性能成本。

## 创意质量门槛

拒绝以下方向：

- 用户输入与画面变化没有可理解的关系。
- 动画只有自动播放，没有交互带来的新信息或反馈。
- 静止状态不成立，必须一直运动才能看懂。
- 用高成本栅格视频实现简单几何运动。
- 为了使用已有视频而强行选择不匹配的参数模型。
- 只能在演示尺寸成立，缩小或触屏后失去意义。
- 滥用堆砌机械电路、赛博霓虹、发光细线等 AI 默认套路杂质，以表面噪点掩盖结构与镜头缺陷，破坏画面焦点与视觉呼吸感。

选定方向后，把它转换为 Motion Brief，再进入资源预算、生成和实现。
